## Implemented contract

`agent_formats.<destination>: omp` opts in to managed OMP Markdown, leaving the default raw link behavior and other providers unchanged. Optional `agent_overlays.<destination>.<agent-name>` has `frontmatter` and `instructions`; see README for a complete two-role example. `frontmatter` supports the checked OMP subset `thinkingLevel`, `autoloadSkills`, `tools`, `spawns`, `blocking`, `readSummarize`. Unknown fields, `model`, empty `spawns`, malformed values, non-OMP overlay destinations, and overlay roles absent from the selected source set block instead of being silently lost. Selection filters do not remove role validation against discovered source inventory. `instructions` is optional single-line text appended to the canonical body. No model is emitted. The config serializer preserves overlay text using YAML single-quoted scalars; the simple parser now decodes doubled single quotes, preserving literal backslashes within these scalars.

OMP generated comments use a distinct checksum marker so format changes to/from OpenCode can be recognized. Local/unmanaged files and legacy raw links are not adopted into native projections, including with `--adopt`; migration needs manual backup and explicit overlay review. The canonical source fields other than name, description and `advertise: true` still block native conversion; no source policy is silently discarded. OMP reserves `main` and `sub`.

OMP 18.16.0 implementation evidence: [helpers.ts at tag commit 650f3a108229ee11bf68ba3377f4e8c3391cd424](https://github.com/can1357/oh-my-pi/blob/650f3a108229ee11bf68ba3377f4e8c3391cd424/packages/coding-agent/src/discovery/helpers.ts) uses `thinkingLevel`, `autoloadSkills`, and maps empty spawns to undefined; [task discovery docs](https://github.com/can1357/oh-my-pi/blob/650f3a108229ee11bf68ba3377f4e8c3391cd424/docs/task-agent-discovery.md) describe frontmatter normalization and discovery. `Do not spawn nested task children.` is a behavioral instruction, not a permission control; omission of `spawns` is not a denial. No runtime launch, autoload effectiveness, or per-run model selector behavior has been proven. Model availability, actual OMP role discovery, and task launch behavior require a separate isolated OMP 18.16.0 runtime test before activation.

Review the successor dossier before integrating either branch.

Automatic second-sync updates of existing OMP, Codex, and OpenCode managed files remain **blocked**, even for an unmodified projection when source or overlay changes. Existing checksum markers can detect old-content ownership, but a portable check then `replace` can clobber an edit made between check and replacement. An atomic rename exchange or OS-specific compare/swap protocol needs careful displaced-file recovery and concurrent-edit guarantees; adding it here would broaden the change and still require cross-platform review. Blocking is the existing safety contract, not completed automatic sync. Source-only and local-edit cases are separately tested and preserved without modification, including with `--adopt`. Stop consumers and writers, inspect the old projection, move it to a safe operator-chosen backup outside discovery, rerun sync, and inspect the result. A removed, renamed, or malformed source also requires manual reconciliation.

Initial native creation is no-clobber; updates remain manual. Multi-file apply, skill+agent apply, and migrations are not transactional. A caught partial failure reports completed paths and backup location where applicable, but abrupt failure may not; inspect before retry. Concurrent uncooperative writers remain a limitation even during manual retirement. Checksums are ownership/conflict hints, not authentication against a malicious writer.
