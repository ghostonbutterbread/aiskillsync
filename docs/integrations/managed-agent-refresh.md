## Contract

Unmodified generated Codex, OpenCode and OMP agents refresh after source or overlay changes; an edited or unmanaged native conflict requires explicit `--adopt` (not `sync all --overwrite`). Legacy raw links can be explicitly adopted. Raw-link adoption uses the same safe displacement protocol, fixing the old final-check-then-unlink pathname deletion race. Missing/renamed sources and source aliases remain blocked. Dry runs and no-ops do not write.

For a regular file the plan captures known previous bytes; apply creates an exclusive independent snapshot, verifies it against the plan, and moves the actual entry by rename into a freshly created private directory on the same filesystem. It checks the moved identity and bytes before a no-clobber publish. A competing entry moved by the rename remains quarantined; a newly created target is never overwritten. The independent snapshot preserves known bytes while the displaced inode retains writes through an open descriptor, even after return. No claim is made to detect those later writes. Snapshot symlinks preserve link text; directory snapshots are non-atomic copies, while their original directory inode is separately retained. Unrelated hostile mutation of private backup directories and power-loss fsync are outside the contract.

The printed recovery index holds the snapshot and a JSON pointer to the private receipt with target, snapshot, displaced path and complete/incomplete status. It is flushed before apply. Caught failures report completed paths and backup root; crash after move leaves the receipt, snapshot and moved inode for manual recovery. A crash before receipt/index creation cannot have displaced the target. Never automatically restore over a destination. The private directory is normally adjacent to the discovery root, with a hidden subdirectory fallback for a mount boundary or permissions; recursive consumer discovery must be checked before activation. Multi-file, skills+agents, and profile-plan applies are not atomic.
