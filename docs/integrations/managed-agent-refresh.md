## Contract decision and remaining boundary

Operators must prevent concurrent renaming or reparenting of configured source and destination roots during sync. Bound directory descriptors preserve the original root-symlink-swap protections: a replacement symlink is not followed to overwrite or delete preexisting protected source entries. If another writer instead moves the **already bound directory inode itself** under a protected source, an fd-relative publication can create a new entry there. This cannot be excluded by checking a path before writing, and this proposal does not claim it can. When the relocation is detected, apply reports incomplete, retains adoption originals and snapshots, and reports the bound directory's device/inode and, when available, an observed location which can itself change. Configured target paths in errors and receipts are not necessarily the entries' current locations. Detection is not an atomic guarantee against an adversary moving a root away and back between checks. Stop consumers and locate and preserve all entries before manually reconciling.

## Implemented candidate and boundaries

- Existing roots are opened and their `fstat` identity and actual source separation are checked during planning and apply. Apply holds descriptors and uses descriptor-relative stat, reads, creation, exclusive publication, snapshots, displaced backups and receipts. Missing roots use no-follow traversal; configured symlink roots remain supported. The backup parent is independently bound, not reached through `..` from a moved destination.
- Destination originals get an independent snapshot and a same-filesystem private displaced inode. Exclusive `renameat2(RENAME_NOREPLACE)` on Linux and `renameatx_np(RENAME_EXCL)` on Darwin prevent clobbering an independently occupied displacement slot; unsupported platforms/filesystems fail rather than falling back to unsafe rename. Linux was exercised; actual Darwin and real cross-mount cases require platform verification. Backups inside selected discovery roots are refused; an unavailable writable same-filesystem ancestor outside discovery blocks adoption/refresh.
- Receipts remain incomplete through actions, bound roots are rechecked before and after completing receipts, and later failures attempt to mark completed receipts incomplete again. If repair fails, the error says so; receipt writes and multi-action apply are not power-loss transactional. An open descriptor can still change the displaced inode after return. Unrelated direct mutation of private backup directories is outside the contract.
- OMP, OpenCode and Codex native refresh, raw link adoption, explicitly adopted local/legacy entries, exact source-byte digest, planned ownership snapshots and late-writer preservation remain in scope. No runtime activation is implied.
