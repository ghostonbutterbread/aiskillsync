## Data-preservation blocker and reproduction

A private same-filesystem rename followed by identity/digest recheck and exclusive publish protects against a concurrent *pathname replacement* at the move: the unexpected entry is quarantined and a later independently created destination is not overwritten. But a writer that opened the old inode before the move retains a writable handle after it. In a real two-process test, after rename, backup verification and successful exclusive publish, that writer truncated and rewrote the old inode. The supposed backup then contained only the late user replacement, not the verified original; the published projection still contained generated bytes and no incomplete receipt was possible. No amount of one-time lstat/digest checking can observe a write occurring after the check or return. A stopped-writer **assumption**, advisory locks, private directory permissions, and rename alone do not revoke already-open descriptors. Without an enforceable exclusion/snapshot contract or an explicitly accepted quiescence precondition and revised backup/concurrency guarantees, this proposal cannot honestly guarantee both exact persistent old bytes and detection/reporting of the concurrent edit. Do not implement silent check-then-replace or call the stopped-writer assumption verified. This does not claim all filesystem-specific designs are impossible; identify and validate their portability and contract before adoption.

The deterministic repro is `docs/integrations/managed-agent-refresh-race-probe.py`: set HOME, all XDG directories and TMPDIR to private fixture directories before running `PYTHONPATH="$PWD" python docs/integrations/managed-agent-refresh-race-probe.py` from the worktree. It creates only a fresh temporary fixture. Besides the open-fd case, it demonstrates pathname replacement quarantine and no-clobber publish, and a child exiting immediately after rename leaving a recoverable backup but an absent active destination. This models abrupt process exit, not power-loss durability or directory `fsync`.

**Separate existing defect:** the same probe calls current raw `_move_no_clobber` with an instrumented replacement at the final `Path.unlink` after the identity check. The concurrently installed user entry is removed, while the backup contains the earlier file. No production change was made to that path; README now explicitly warns to stop all writers. Do not infer race safety from the existing no-clobber-backup tests. This is within the affected agent adoption owner, but not repaired by the parser-only checkpoint.
