## Intent and contract

Add explicitly configured, source-prompt-preserving generated files for Codex standalone agent TOML and OpenCode subagent Markdown. Models are not pinned. OpenCode output sets `permission.task: deny`; Codex inherits the parent's permissions and relies on source instructions / runtime limits rather than claiming equivalent enforcement. Native conversion accepts name, description, and `advertise: true`, but blocks `advertise: false` and other source fields. True is translated only to a native role file, not a promise of equivalent parent-prompt advertisement; Codex discovery remains unverified. Source/destination root overlap blocks. New files use no-clobber creation; existing changed native files always block and require the operator-owned stop-consumer, move-to-backup, recreate/restore workflow in README. Identifiable stale, malformed, renamed and changed-format definitions block rather than disappearing or remaining silently active; raw links with selected source roots are checked too. Multi-file failure reports completed paths and backup location, with manual recovery; it is not a transaction. Different-source/lane ownership requires explicit reconciliation.

## Blockers and deferred work

1. **OMP safety and per-invocation routing:** upstream `parseAgentFields` calls `parseArrayOrCSV([])` which yields `undefined`; `resolveSpawnPolicy(undefined)` is unrestricted. Thus existing `spawns: []` cannot be assumed effective, and projecting it would make a false safety claim. Exact installed Hoster OMP revision and behavior are unverified. Need an upstream-fixed or otherwise tested no-delegation contract, plus reconciliation of local prompt/tool/skill-preload fields and a version-matched isolated native loader + spawn-policy test before adding an OMP format. Do not overwrite local OMP definitions; legacy raw-link adoption remains separately dangerous and parent must evaluate it.
2. **Codex loader:** current OpenAI docs specify standalone TOML auto-discovery, but installed host version and native invocation were not verified. In a disposable credential-free `CODEX_HOME`, use the exact intended Codex version and its actual discovery interface to confirm role name, instructions and inherited settings; if it only supports config-registered roles, registration must be separately designed and tested. A `tomllib` parse does not establish discovery.
3. **OpenCode semantics:** loader discovery is verified in fixture only; exact target version, child prompt/permission enforcement and model routing per spawn are not verified. Use a disposable fixture and non-network test provider/loader API before activation. Per-call model choice is runtime/version dependent; unpinned is not equivalent to per-call support.
4. **Pi / Claude:** no Pi extension contract was verified, and Claude remains legacy raw Markdown only, not an adapted projection; do not report native compatibility for a path alone. Review exact extension version and Claude loader before any claimed end-to-end coverage.
5. **Activation:** no Hoster writes or runtime configuration changes are authorized by this branch. Parent must inspect same-name definitions and migrate their distinct bodies, preloads, and safety constraints explicitly; backups alone do not reconcile them. Preserve unresolved files and report conflicts.
6. **Base blockers:** the switch and double-effective-lane fixes are present in the joint checkpoint. A subsequent independent review found `_source_entries` fails to retain intermediate directory symlink entries; adopting a destination directory symlink referenced by another source can redirect or break that source. Parent must reproduce and fix this on the combined branch, test it, and secure fresh independent review before integration.
7. **Recoverability limitations:** native refresh requires stopped-consumer manual retirement and reconciliation, not automatic `sync all` updates. A source change detected after publication leaves a potentially active stale file and reports its path; stop the consumer and reconcile. Partial writes are explicitly reported but not rolled back; abrupt termination can omit receipts, and skill, profile, and agent plans are not one transaction. Source checks and no-clobber creates do not fence changes immediately after their last check or arbitrary writers. The native review's concurrent-adoption and stale-skip risks are inspection-only; no race-proof guarantee is claimed. Directory backups and cross-filesystem copies are non-atomic and can leave partial backups; stop writers before adopting, particularly since nested directory edits aren't all detectable. Filesystems that reject hard links for reasons other than cross-device failure block adoption. Marker removal/corruption makes retired files unidentifiable without a manifest; raw links to a removed source root likewise cannot be proven owned. Unmatched native markers from a different profile sharing a root conservatively block. A durable manifest/transaction would need a separate design and race analysis; never treat these cases as silently safe.
