## Intent and contract

Repair the shared-parser compatibility regressions identified in independent review without losing safe new OMP escape handling. Legacy scalar parsing and list/delimiter behavior follow the pre-`da2c6e8` implementation: in particular double-quoted backslashes are literal, unknown escapes and previously accepted single-quote/unterminated scalars retain prior meaning. The parser switches to strict JSON-compatible double-quoted escapes only within the root `agent_overlays` subtree, including block and inline lists. Unsupported escapes and unpaired decoded Unicode surrogates are `ConfigError`s. Overlay values must remain single-line; non-CR/LF splitlines separators inside the subtree are rejected before they can silently split an instruction. Actual Unicode characters formed by a valid surrogate pair remain supported.

Config serialization uses single-quoted scalar escaping where necessary and verifies that the resulting UTF-8 text reparses into the identical `Config`; values or mapping keys the existing subset cannot represent are rejected with `ConfigError` rather than silently changed. Empty default destination lists and colon-containing list items round-trip. Actual tabs in valid bridge names and mapping keys are preserved. Direct repo/external add and repo remove compute the intended complete parsed mapping, compare it with the candidate text (including unknown fields), and validate it as a `Config` before writing; unsafe edits fail without changing the original. This does not claim to implement general YAML. README documents the scope. The inherited managed-refresh dossier describes the historical `da2c6e8` parser behavior; this proposal supersedes that parser assessment only, not its refresh or raw-adoption safety blockers.

**Known editor limitation:** indentless bridge sequences are accepted by the parser but the existing text-edit span locator does not support them. When it cannot select the intended span safely, repo removal now fails closed rather than deleting another entry. Editing those configs manually or converting the sequence to indented form remains necessary; no automatic layout rewrite was added.
